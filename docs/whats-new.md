# What's new per topic

Read before editing content/news, docs/news-state.json or the routine files.

- Data: `content/news/<slug>.json` is `{ asOf, items }`, at most 3 items, zero is valid and renders nothing. An item has `id`, `kind` (release, engineering-post, standard, docs), `title`, `publisher`, `url`, `dateShown` (YYYY-MM-DD, YYYY-MM, YYYY or "no date shown", exactly what the page shows), `summary`, `evidence`, `addedOn`, `verifiedOn`.
- Summary: one plain sentence of 12 to 30 words in our own words, no em dash or "not X but Y". Any digit must also be in the evidence. Any digit or comparative word (faster, higher, lower, more, less, better, improves) needs an attribution phrase (says, reports, claims, describes) naming the publisher's first word.
- Evidence: a phrase of at most 15 words copied from the page text. Never displayed; only the checkers read it.
- Allowlist: `docs/news-state.json` `allowedDomains[slug]` is a list of `{ host, pathPrefix?, publisher, kinds? }`. A host matches exactly or as a true subdomain, never by substring. https only, no credentials, no other port. A prefix needs a path boundary. The item's `publisher` must equal the entry's `publisher` string, and `kinds` (if set) limits the item's kind. Only a person edits the allowlist; a `claude/` pull request that changes it fails the guard. `lastChecked[slug]` is the last routine run for that topic.
- Checks: `scripts/news-rules.mjs` holds every rule once. `scripts/check-news.mjs` runs in the build (errors fail, dates older than 12 months warn). `npm run verify:news` needs the network: it fetches each page raw (Wayback copy when blocked, marked "archive copy"), follows redirects by hand and refuses any hop outside the allowlist, confirms the evidence is in the page text and `dateShown` matches a date the page shows, and fails items older than 12 months.
- Page: "What's new in <Topic>" with "As of <asOf>" after What to learn next and before Original posts. Not tracked, not in the rail, searchable (its own `data-pagefind-body`, the heading is the label), sitemap lastmod includes `asOf`. The note says "reviewed by me before publishing" only when `NEWS_MODE` in lib/site.ts is "review"; About follows the same constant. Change NEWS_MODE together with the NEWS_AUTOMERGE variable.
- The routine may touch only `content/news/**` and `docs/news-state.json`. It never edits topics, digests, code or docs, and never pushes to main.
- Pull requests: `.github/workflows/news-pr.yml` runs on `pull_request_target`, so the workflow and scripts always come from the base branch. `scripts/news-guard.mjs` allows a news pull request to change only `content/news/**/*.json` and `docs/news-state.json`. CODEOWNERS covers everything else that matters. Setup and the test pull request to run before auto-merge: docs/routines/README.md.
