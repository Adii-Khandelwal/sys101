# Guided tours

A short, optional tour on the home page and on topic pages. Entry is a quiet text link, "Take the 30-second tour": in the masthead on Home, in the "Skip to the posts" row on a topic page. It never starts by itself.

- **Steps** live in `lib/tours.ts` (at most five a page, plain text, an optional phone wording or target, `desktopOnly` for the Map/Path step). Each step names a `data-tour` target; the matching attribute sits on an existing element (`map`, `states`, `view`, `search`, `your-data`, `jump`, `progress`, `check`, `posts`, `exercises`). A step whose target is missing or hidden is skipped, so a topic with no Background link or a phone with no Map toggle still gets a coherent tour. A test checks that every target exists in the source.
- **Check each step's text against the site** whenever the page it points at changes: the tour says what the page does today (states, Mark done, quiz explanations, the `/` shortcut, multi-word search).
- **Look.** A thin `--accent` outline around the target and a light dim: `--paper` at 0.55 opacity. One full-screen SVG draws them: the dim is four rects around the target, the outline one rect (non-scaling 2px stroke), each a 1 x 1 square placed with `translate` and `scale`, so there is no `clip-path` and no `box-shadow`. No blur, glow or gradient. The tooltip is a 1px `--ink` box with a 2px radius.
- **Motion.** Going to the next step, the outline, the dim and the tooltip glide to the new place by `transform` only: `--dur-base` (200ms) with `--ease-in-out`, the site's movement curve. Transitions retarget from where they are, so a quick second press is fine. The first step does not glide (it fades in at `--dur-fast`), and following a scroll or resize snaps with no transition so the outline never lags the page. Under reduced motion the tokens are 0ms, so every step jumps. Scrolling to a target stays instant. `npm run check:tour` checks both the glide and the jump. On a phone the tooltip is docked and does not move.
- **Behaviour.** The dim ignores the pointer, so the page stays clickable. Focus moves into the tooltip and Tab wraps around Back / Next / Skip; the arrows step; Esc closes; closing returns focus to the entry link and puts the scroll position back. An `aria-live="polite"` region announces "Step n of N: title. text". On a phone the tooltip docks to the bottom edge.
- **Shown until used, then quiet.** The link must not nag on every visit. Closing a tour any way (Done, Skip, Esc) stores `sys101:tours` = `{version: 1, seen: {home?, topic?}}` (`lib/tourSeen.ts`; every read and write guarded, damaged data counts as unseen; not part of the progress store, export or import). On later visits that tour's link is not rendered. It stays on the current page until the next visit, so focus has somewhere to return. Your data has a "Show the tour links again" button; Privacy and About say the flag is stored. The tour never starts by itself and never shows a nudge.
- **Reading tracker.** While a tour runs, `document.documentElement.dataset.touring` stops the reading tracker (`components/LessonRail.tsx`) from recording the tour's scrolling as visits, and closing puts the scroll position back.
- **Loading.** `TourLink` (in the page) is a button; `TourOverlay` and the step text load by `next/dynamic` only when it is pressed. Without JavaScript the button stays invisible (its space is kept).
- **Checks.** `lib/tours.test.ts` (steps, wording, keys, hole path, no storage) and `npm run check:tour` (a real browser against a running server: keyboard flow, Esc, focus return, Skip, the page stays clickable, docking and 44px buttons at 390px).
