## Agreement and differences

- Idempotency keys: Stripe (S3), Square (S7), Adyen (S10), TigerBeetle (S17), Fowler (S21), Azure (S25) agree that a repeated request must have the same effect as one request. Azure (S25) and Fowler (S21) frame it on the receiving side; Stripe, Square and Adyen on the API side.
- Webhooks: Stripe (S4), Adyen (S9), Razorpay (S13) agree on signed, asynchronous events. Razorpay S13 uses an HMAC-style header; Stripe S4 stresses the raw body. Retry behaviour is on the Stripe page but only with figures, so it is not recorded.
- Authorize then capture: Stripe (S5), Adyen (S8), Razorpay (S12) agree, and differ on the default (Adyen and Razorpay capture automatically by default; Stripe describes manual capture as an option).
- Double entry: Fowler (S20) and TigerBeetle (S17). Only these two.
- Estimation: S27 and S30 differ (see table).
- Retries: Azure S22/S23 and AWS S26 agree that retrying has a cost and a breaker or backoff limits it.
