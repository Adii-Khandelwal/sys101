# Graph

Applies when editing the map, its layout or the node-open transition.

## Standing rules

- The map is the homepage on desktop (768px and up); under 768px only the Path view is shown, with no Map/Path toggle; the toggle on desktop remembers an explicit choice.
- Layout is deterministic and static. Draw only the transitive reduction by default. No edge crosses a label or node.
- Node states never rely on color alone: unread (thin outline), ready (thicker outline + centre dot), in progress (accent outline + accent centre dot, for a topic deliberately started), read (filled accent). In progress ranks above ready. The Path view shows the same legend (components/StateLegend.tsx) above its list, and names what each topic builds on before the reasons.
- The map has no zoom: no wheel, pinch, double-click or key zoom, no "Fit to size" button and no "Scroll sideways" cue (owner decision, 29 Oct 2026). It renders at one fixed scale and scrolls sideways natively (trackpad, wheel, touch, scrollbar) inside `.graph-scrollwrap`, with scroll-snap marks between columns; a mouse can also drag it sideways. A phone has no map (Path view). Keep a plain text index and keyboard use as the fallback.
- After adding a topic, run lib/metroRoute.test.ts (zero crossings and overlaps at 1280px and 1440px) (a phone has no map, only the Path view, so there is no 390px map check).

## Renderer (Phase 4a of the redesign; one SVG, no Sigma, no graphology)

- `components/GraphView.tsx` draws the map as one `<svg class="graph-canvas">` on the existing layout (`lib/graph.ts`, `chooseLayers`, `fitPositions`, `edgeCurvatures`; nothing about the layout changed). The layout effect stores node positions in stage pixels (y down) in `Layout`; they are also the screen pixels inside the stage (there is no camera; `lib/camera.ts` is gone). Edges are metro lines from `routeEdges` (lib/metroRoute.ts, pure, tested in lib/metroRoute.test.ts): an edge leaves its station horizontally, jogs on a vertical between columns with 9px, 45-degree chamfers, and enters the next station horizontally, with a small arrowhead from `routeShape`. A long edge passes through its reserved corridor slots. The jog of each segment sits in the strip between the end of its column's widest label and the arrowhead run into the next column, chosen to cross nothing; edges from one source, or into one target, may share a trunk. Hidden edges are dashed hints from `routeHidden` (a lane between rows, off every station and label, allowed to cross other lines).
- Every colour is a CSS variable in `app/globals.css` (`.graph-node`, `.graph-edge`, `.graph-label`), so a theme change needs no repaint and no JS theme sync. State is shown by `data-read`, `data-ready`, `data-progress`, `data-lit`, `data-active`, `data-faded` on the node group; fading is opacity 0.6 on shapes and edges, and labels switch to `--ink-soft`.
- Each node is a real `<a class="graph-node-link" href>` in the SVG with a transparent 22px-radius hit circle (44px), a focus ring circle (`:focus-visible`, accent) and an aria-label. Tab order is the data order; Ctrl, Cmd, middle click and Enter work as a link does. NextUp focuses `.graph-node-link[href]`.
- The metro look (4b): labels hang under their station, left-aligned with the station's left edge (`LABEL_LEFT` 14px, baseline `LABEL_BASELINE` 34px below the centre); stations keep the four states by shape (unread a 2.5px ring; ready a 4.5px ring and a centre dot; in progress the same in `--accent`; read filled `--accent`); lit lines are overprinted in `--ink2`; one hand-drawn ring (`handRing`, `--ink2`, never animated) goes round the current station only (`ringFor` sizes it to the station and the first 150px of its label; the test checks it covers no other station or label, but it is drawn over lines and may cross them on purpose) (a topic in progress, else the first topic when nothing is read, else the best ready one, which approximates the Next up button without its lesson data); four hairline crop-mark ticks sit just outside the chart frame (`.graph-frame`, no crosshair, no grain, no dots); the 1.5px `--ink` frame is the scroll wrapper's border; group names are framed Cabin badges (`.graph-group`, reversed out when pressed, 32px badge with a 44px tap area).
- Behaviour (4c, zoom removed in 4e): Arrow keys on a focused station (`nextStation`, lib/graphUi.ts): left to the nearest prerequisite, right to the nearest topic that builds on it, up and down along the column; Enter opens. Arrow keys are always taken (a column's end does nothing, the browser never scrolls the map instead), focus does not scroll the page, and the station and the start of its label are brought into view: the sideways scroll lands on the nearest snap mark that still shows it (`revealDelta`, lib/graphUi.ts). The link's own name (aria-label) says title, post count and state; one visually hidden polite live region in the stage adds only what it builds on and what to finish first, and is cleared on blur and Escape. Each node link carries `data-own-transition` because the page-wide link handlers (ViewTransitions, NavPending) read `a.href`, which is an SVGAnimatedString on an SVG link.

## Specification

(Where this section still says Sigma, WebGL, a canvas, curves, or labels to the right of a node, read the SVG metro renderer above.)

- The graph is the homepage on desktop (768px and up). Under 768px the homepage shows only the Path view (components/PathView.tsx), a linear grouped syllabus, with no toggle; on desktop a Map/Path toggle switches between them and the choice is remembered per browser. Layout is deterministic, left to right by prerequisite depth, and panning never moves nodes.
- On desktop (768px and up) the map is always a full-size horizontal graph (labels at full size, never shrunk or stacked) at one fixed scale: GraphView lays it out across the width its labels need, and the stage renders at that content width inside a horizontally-scrolling wrapper (`.graph-scrollwrap`), so when the map is wider than the viewport the whole map section scrolls sideways with a real scrollbar, a trackpad, a wheel, a finger or a mouse drag (snap off while dragging; a press that moves less than 5px is a click). The wrapper uses `scroll-snap-type: x proximity` with zero-size `.graph-snap` marks at the right edge of each column's widest label, so a scroll ends between columns, never through a label; the first, unscrolled view still cuts where the stage is wider than the window. The viewport width is measured on the wrapper and the stage width is driven by the computed content width, so they never feed back on each other. A phone shows only the Path view and GraphView skips the layout there. After adding a topic, run lib/metroRoute.test.ts.
- Nothing on the map captures the page's vertical scroll or a touch (`touch-action: auto`); wheel and trackpad sideways scrolling are the browser's own.
- Draw only the transitive reduction of prerequisites by default. Hidden edges show faintly on hover or focus. Data and build checks use the full set.
- Node states that do not rely on color: unread (thin outline), ready (all prerequisites read, thicker outline), read (filled accent). Not-yet nodes stay clickable.
- No edge crosses a label, a station or another unrelated edge (shared trunks excepted); lib/metroRoute.test.ts checks all topics at 1280px and 1440px, with labels 25% wider, and every growing prefix from 3 to all topics. Labels sit under their station; `MIN_LABEL_GAP` is 40px (it was 16 for right-hand labels) so each gap holds a strip for the elbow jogs, and the tests use glyph widths measured in the browser (a table in the test), not a per-character guess. Tooltips are viewport-clamped and never clipped. The first tooltip opens after 300ms of hovering or focus; a neighbouring node's opens at once, until 150ms pass with no tooltip; keyboard focus never waits (TIP_DELAY_MS, TIP_COOL_MS in components/GraphView.tsx). Unrelated items fade to no lower than 60% opacity, and highlight always clears.
- Group names sit in one row between the legend and the map frame (`.graph-groups`, framed Cabin badges 32px tall with a 44px `::after` hit area), each with its topic count ("Reliability · 6"). They are never drawn inside the map, so no edge or label can collide with one.
- Group names are real buttons (`aria-pressed`): clicking one highlights just that group's topics (its nodes stay opaque, the rest fade to no lower than 60%, like a node highlight), with the pressed badge reversed out (paper text on an `--ink` fill, a shape change as well as a colour one). Clicking it again, Escape, a scroll, or a click outside clears it; hovering or focusing a node takes over. Computed by groupSet in lib/graphUi.ts.
- Keyboard traversal, aria-live announcements, 44px hit areas, and the plain text index (All topics) as the full fallback and the no-JavaScript view. Smooth at 150 nodes.
- Pivot trigger: when the graph stops being readable (crowded nodes or unreadable edges), the Path view is the fallback. The Path view and the mobile Path default under 768px are built; see docs/ideas.md ideas 5 and 6.
- Touch: a finger scrolls the map sideways and the page vertically, and a tap opens the topic. There is no pinch.

## Node-open transition (the one exception to the page fade-in rule in CLAUDE.md)

- A plain pointer click or touch tap on a Map node plays this, about 530ms when the page is ready: the node's bubble grows in ONE continuous motion (three base durations, one easing) while a screen in the page colour fades in over the map in the first base duration, so the map dissolves and the bubble keeps growing on the plain screen. Once the screen is fully in, the topic page loads behind it. At 55% of the growth, when the bubble is at its fastest, and once the page has arrived, the bubble bursts: it pops outward and fades (fast), a thin shock ring flies past it, and the screen fades out (base) to show the topic. This is the exception to "never fade in the page": the page appears by a fade after a node click, never on a direct load.
- The bubble is also the page loader. If the page is slower than the growth (the first click under `npm run dev` compiles the route, seconds), the bubble reaches full size, then breathes (a 6% scale pulse on the `--dur-pulse` token) until the page arrives, then bursts.
- Why this shape: the page swap holds the main thread for a moment (50ms normally, 150ms or more on a slow CPU). Doing it behind a plain, static screen while the compositor keeps growing the bubble makes the stall invisible. Earlier versions grew, stopped, then faded; they froze mid-motion at the swap, and a second ease that started from rest after the first one ended read as a pause. One easing and a burst at peak speed remove both. Only `transform` and `opacity` are animated. Measured on a production build: steady 17ms frames from click to finish, unthrottled and with a 4x slower CPU; the bubble's size grows with rising speed up to the burst.
- The bubble is a DOM copy of the node (ring, fill, centre dot, same colours) built at its largest size and scaled DOWN to the node's size to start, so it is exactly over the node (nothing flashes) and stays crisp when it grows. The screen, bubble and shock ring are plain elements on `document.body` (not in React), so they survive the page swap; `playNodeOpen` in lib/nodeOpen.ts owns the sequence and removes them at the end, on cancel, after a 6s safety limit, and on `pageshow` from the back/forward cache.
- Plays only from `openNode` in components/GraphView.tsx, built from the station's own circle (`stationSpec`: centre from its rect, ring width, fill and centre dot from its computed paint, so every state and both themes copy as drawn). Path view, search, the All-topics index and direct links never import it, and keep the ordinary page cross-fade. No dependency on the View Transitions API.
- `clickIntent` decides: Ctrl, Cmd, Shift or Alt held, or a middle click, opens a new tab with no animation; reduced motion, or a click with detail 0 (script or assistive technology), opens at once; a keyboard Enter on a node's link is the plain link, untouched. A second click, or the second click of a double click (`detail` 2), cancels the opening that is playing and starts nothing (`pendingOpen`, `isActive`); a cancel before the page swap means the page never loads. The opening is not a link click, so NavPending's slow-page loader does not run for Map nodes, including the reduced-motion path that goes straight to the page.
- First paint: the skeleton stays until the layout effect has placed every node (`placed` in `components/GraphView.tsx`; the canvas is `visibility: hidden` until then), so the map never shows its nodes stacked at the origin and then spreading out. `chooseLayers` (about 0.7s of search) is remembered per input set in memory and in sessionStorage (`sys101:layers`, slugs only, 12 entries), so a refresh in the same tab and a return to the homepage skip it; only a tab's first visit pays once, behind the skeleton.
- Back keeps the view: when a node is opened the sideways scroll is saved to sessionStorage (lib/mapView.ts, version 3: only `scrollLeft`; versions 1 and 2 saved a zoom camera and are ignored). The Map restores it once if it mounts right after a popstate (Back or Forward) and the data is under 30 minutes old; any other visit starts at the left.
- Judge smoothness on `npm run build && npm start`: under `npm run dev` the first click on each topic compiles its route, and the loader state is what you see.
- The Map is not shown under 768px (the Path view is), so the animation is for pointer and touch devices at 768px and up.

## Frame and sign (Phase 4d)

- The state legend (`StateLegend`, once per view: here in `.graph-toolbar`, in its own row above the group badges and outside the frame; the Path view has its own) is a framed bar (1.5px `--ink` square frame, Cabin 13px) of the four station marks, each followed by its lowercase word on one row: not started, ready to read, in progress, read. The words and look are the same in both views (one component, so they cannot differ); it wraps with a gap on narrow widths. The frame's bottom edge is a plain frame line. `GraphView` takes an optional `onActive(slug | null)` called with the hovered or focused station; the station sign under the map follows it (homepage.md).
