# Graph

Applies when editing the map, its layout or the node-open transition.

## Standing rules

- The map is the homepage on desktop (768px and up); under 768px only the Path view is shown, with no Map/Path toggle; the toggle on desktop remembers an explicit choice.
- Layout is deterministic and static. Draw only the transitive reduction by default. No edge crosses a label or node.
- Node states never rely on color alone: unread (thin outline), ready (thicker outline + centre dot), in progress (accent outline + accent centre dot, for a topic deliberately started), read (filled accent). In progress ranks above ready. The Path view shows the same legend (components/StateLegend.tsx) above its list, and names what each topic builds on before the reasons.
- Pan is desktop-only and starts at INTERACTIVE_MIN_NODES topics; zoom is keyboard-only (`+`/`-`/`0`, which never animate; only the "Fit to size" button eases). Zoom and Show all links have no on-screen buttons (camera and edge-filter state stay); the one exception is a "Fit to size" text button on an interactive map, disabled while the view is fitted. A phone gets the fixed map. Keep a plain text index and keyboard use as the fallback.
- After adding a topic, check the map at 1280px and 1440px for zero crossings and overlaps (a phone has no map, only the Path view, so there is no 390px map check). At 1280px also test that sideways page scroll and map pan do not conflict.

## Specification

- The graph is the homepage on desktop (768px and up). Under 768px the homepage shows only the Path view (components/PathView.tsx), a linear grouped syllabus, with no toggle; on desktop a Map/Path toggle switches between them and the choice is remembered per browser. Layout is deterministic, left to right by prerequisite depth, and panning never moves nodes.
- Under INTERACTIVE_MIN_NODES topics (12, in lib/graphUi.ts), or on a phone (under 768px) at any count, the map is fixed and fitted: no zoom, pan, or map controls, and clicking a node cross-fades to its topic. On a phone the homepage shows only the Path view, and GraphView skips importing the map libraries (Sigma, graphology, about 190 KB) there; a fixed map is what a phone would get so a finger scrolls the page past it and a tap opens the topic; zoom and pan are desktop-only. At 768px and up, from INTERACTIVE_MIN_NODES topics the zoom/pan/Fit-all controls switch on. On desktop the map is always a full-size horizontal graph (labels at full size, never shrunk or stacked): GraphView lays it out across the width its labels need, and the stage renders at that content width inside a horizontally-scrolling wrapper (components, `.graph-scrollwrap`), so when the map is wider than the viewport the whole map section scrolls sideways with a real scrollbar. A quiet "Scroll sideways for more" cue in the legend row shows while there is more to the right and hides at the end (opacity only, instant under reduced motion). The wrapper uses `scroll-snap-type: x proximity` with zero-size `.graph-snap` marks at the right edge of each column's widest label, so a scroll ends between columns, never through a label; the first, unscrolled view still cuts where the stage is wider than the window. The viewport width is measured on the wrapper and the stage width is driven by the computed content width, so they never feed back on each other. The map is static: a node click just highlights briefly and cross-fades (no camera recentre). A phone stacks vertically, one topic per row. After adding a topic, check the map at 1280px, 1440px, and 390px for zero crossings and overlaps.
- One fitRatio, recomputed on load, resize, and node-set change. Zoom range 0.6x to 8x of the fitted view, with identical limits for wheel, pinch, buttons, keys, and double-click. Ctrl or Cmd plus wheel zooms and plain wheel scrolls the page. Fit all always restores the identical state. 5px drag threshold. 64px pan limit.
- Draw only the transitive reduction of prerequisites by default. Hidden edges show faintly on hover or focus, and with "Show all links" once the map is interactive. Data and build checks use the full set.
- Node states that do not rely on color: unread (thin outline), ready (all prerequisites read, thicker outline), read (filled accent). Not-yet nodes stay clickable.
- No edge crosses a label or node. Labels sit right of nodes with a 16px gap. Tooltips are viewport-clamped and never clipped. The first tooltip opens after 300ms of hovering or focus; a neighbouring node's opens at once, until 150ms pass with no tooltip; keyboard focus never waits (TIP_DELAY_MS, TIP_COOL_MS in components/GraphView.tsx). Unrelated items fade to no lower than 60% opacity, and highlight always clears.
- Group names sit in one row between the legend and the map (`.graph-groups`, Cabin labels, 44px tap height), each with its topic count ("Reliability · 6"). They are never drawn inside the map, so no edge or label can collide with one.
- Group names are real buttons (`aria-pressed`): clicking one highlights just that group's topics (its nodes stay opaque, the rest fade to no lower than 60%, like a node highlight), with the pressed name taking the accent and an underline (state by shape, not colour alone). Clicking it again, Escape, a scroll, or a click outside clears it; hovering or focusing a node takes over. Computed by groupSet in lib/graphUi.ts.
- Keyboard traversal, aria-live announcements, 44px hit areas, and a plain text index as the full fallback, including when WebGL fails. Smooth at 150 nodes.
- Pivot trigger: when the graph stops being readable (crowded nodes or unreadable edges), the Path view is the fallback. The Path view and the mobile Path default under 768px are built; see docs/ideas.md ideas 5 and 6. (The separate zoom/pan interactivity threshold is INTERACTIVE_MIN_NODES, currently 12; see above.)
- Touch: an interactive map is desktop-only; there one finger pans (the drag follows the finger) and two fingers pinch to zoom. On a phone the map is always fixed and non-interactive, so it captures no touch, a finger scrolls the page past it, a tap opens the topic, and pull to refresh works.

## Node-open transition (the one exception to the page fade-in rule in CLAUDE.md)

- A plain pointer click or touch tap on a Map node plays this, about 530ms when the page is ready: the node's bubble grows in ONE continuous motion (three base durations, one easing) while a screen in the page colour fades in over the map in the first base duration, so the map dissolves and the bubble keeps growing on the plain screen. Once the screen is fully in, the topic page loads behind it. At 55% of the growth, when the bubble is at its fastest, and once the page has arrived, the bubble bursts: it pops outward and fades (fast), a thin shock ring flies past it, and the screen fades out (base) to show the topic. This is the exception to "never fade in the page": the page appears by a fade after a node click, never on a direct load.
- The bubble is also the page loader. If the page is slower than the growth (the first click under `npm run dev` compiles the route, seconds), the bubble reaches full size, then breathes (a 6% scale pulse on the `--dur-pulse` token) until the page arrives, then bursts.
- Why this shape: the page swap holds the main thread for a moment (50ms normally, 150ms or more on a slow CPU). Doing it behind a plain, static screen while the compositor keeps growing the bubble makes the stall invisible. Earlier versions grew, stopped, then faded; they froze mid-motion at the swap, and a second ease that started from rest after the first one ended read as a pause. One easing and a burst at peak speed remove both. Only `transform` and `opacity` are animated. Measured on a production build: steady 17ms frames from click to finish, unthrottled and with a 4x slower CPU; the bubble's size grows with rising speed up to the burst.
- The bubble is a DOM copy of the node (ring, fill, centre dot, same colours) built at its largest size and scaled DOWN to the node's size to start, so it is exactly over the node (nothing flashes) and stays crisp when it grows. The screen, bubble and shock ring are plain elements on `document.body` (not in React), so they survive the page swap; `playNodeOpen` in lib/nodeOpen.ts owns the sequence and removes them at the end, on cancel, after a 6s safety limit, and on `pageshow` from the back/forward cache.
- Plays only from `clickNode` in components/GraphView.tsx. Path view, search, the All-topics index and direct links never import it, and keep the ordinary page cross-fade. No dependency on the View Transitions API.
- `clickIntent` decides: Ctrl, Cmd, Shift or Alt held, or a middle click, opens a new tab with no animation; reduced motion, or a click with detail 0 (script or assistive technology), opens at once; a keyboard Enter on a node's link is the plain link, untouched. A double click, or a second click, cancels it.
- First paint: the skeleton stays until the layout effect has placed every node (`placed` in `components/GraphView.tsx`; the canvas is `visibility: hidden` until then), so the map never shows its nodes stacked at the origin and then spreading out. `chooseLayers` (about 0.7s of search) is remembered per input set in memory and in sessionStorage (`sys101:layers`, slugs only, 12 entries), so a refresh in the same tab and a return to the homepage skip it; only a tab's first visit pays once, behind the skeleton.
- Back keeps the view: when a node is opened the camera and the sideways scroll are saved to sessionStorage (lib/mapView.ts). The Map restores them once if it mounts right after a popstate (Back or Forward) and the data is under 30 minutes old; any other visit starts fitted.
- Judge smoothness on `npm run build && npm start`: under `npm run dev` the first click on each topic compiles its route, and the loader state is what you see.
- The Map is not shown under 768px (the Path view is), so the animation is for pointer and touch devices at 768px and up.
