# Guided tours

Applies when editing the home and topic tours.

## Specification

A short, optional tour on the home page and on topic pages. Entry is a quiet text link, "Take the 30-second tour": in the masthead on Home, in the "Skip to the posts" row on a topic page. It never starts by itself.

- **Steps** live in `lib/tours.ts` (at most five a page, plain text, an optional phone wording or target, `desktopOnly` for the Map/Path step). Each step names a `data-tour` target; the matching attribute sits on an existing element (`map`, `states`, `view`, `search`, `your-data`, `jump`, `progress`, `check`, `posts`, `exercises`). A step whose target is missing or hidden is skipped, so a topic with no Background link or a phone with no Map toggle still gets a coherent tour. A test checks that every target exists in the source.
- **Check each step's text against the site** whenever the page it points at changes: the tour says what the page does today (states, Mark done, quiz explanations, the `/` shortcut, multi-word search).
- **Look.** A thin `--accent` outline around the target and a light dim: `--paper` at 0.55 opacity. One full-screen SVG draws them: the dim is four rects around the target, the outline one rect (non-scaling 2px stroke), each a 1 x 1 square placed with `translate` and `scale`, so there is no `clip-path` and no `box-shadow`. No blur, glow or gradient. The tooltip is a 1px `--ink` box with a 2px radius.
- **Motion.** Every step moves on one eased clock (`animate` in `components/TourOverlay.tsx`, `--ease-in-out` as `bezier(EASING.inOut)`): the page scroll, the outline, the dim and the tooltip start and arrive together, so nothing jumps and nothing lags. TourOverlay first asks the browser where the page will end up (its own centring and sticky-header rules), puts it back with no frame painted, then animates there. A step that only moves the outline takes `--dur-base`; one that moves the page takes `--dur-slow`, plus up to half again for a long way so it does not blur. The first step scrolls with the overlay hidden and fades in on arrival; closing fades out while the page eases to the top. A second press retargets from wherever the outline is. The tooltip words fade in (`--dur-fast`). Following a scroll or resize afterwards snaps. Under reduced motion every step jumps. `npm run check:tour` checks the glide and the jump. On a phone the tooltip is docked and does not move.
- **Behaviour.** A transparent layer (`.tour-block`) catches every click and tap meant for the page behind, including the outlined part, so nothing is pressed by accident; scrolling still works and only the tooltip takes input. Focus moves into the tooltip and Tab wraps around Back / Next / Skip; the arrows step; Esc closes; Esc returns focus to the entry link, and Done or Skip tour (which remove the link) put focus on the page heading without a ring and puts the scroll position back. An `aria-live="polite"` region announces "Step n of N: title. text". On a phone the tooltip docks to the bottom edge.
- **Shown until used, then quiet.** The link must not nag on every visit. Finishing a tour (Done) or pressing Skip tour stores `sys101:tours` = `{version: 1, seen: {home?, topic?}}` (`lib/tourSeen.ts`; every read and write guarded, damaged data counts as unseen; not part of the progress store, export or import). Esc, or a tour that ended because the page changed under it, stores nothing, so the link stays until the reader finishes or skips. On later visits that tour's link is not rendered; the footer link stays. It stays on the current page until the next visit, so focus has somewhere to return. Your data has a "Show the tour links again" button, and "Reset everything" clears the flag too (and is enabled even when no progress was saved); Privacy and About say the flag is stored. The tour never starts by itself and never shows a nudge.
- **Reading tracker.** While a tour runs, `document.documentElement.dataset.touring` stops the reading tracker (`components/LessonRail.tsx`) from recording the tour's scrolling as visits, and closing fades out and eases the page back to its top (smooth, or instant under reduced motion), on a phone as on a desktop, so a reader who closes the tour starts again from the top, and the tracker stays off until it arrives. The entry link on a topic page sits on its own quiet line below the jump links.
- **Loading.** `TourLink` (in the page) is a button; `TourOverlay` and the step text load by `next/dynamic` only when it is pressed. Without JavaScript the button stays invisible (its space is kept).
- **Checks.** `lib/tours.test.ts` (steps, wording, keys, hole path, no storage) and `npm run check:tour` (a real browser against a running server: keyboard flow, Esc, focus return, Skip, the page stays clickable, docking and 44px buttons at 390px).
