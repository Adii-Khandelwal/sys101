# sys101

A system design course built as a prerequisite graph, taught through how real companies engineered each concept.

![The sys101 homepage: a map of four topics, DNS, Load Balancing, Caching and Consistent Hashing, joined by arrows that show which topic builds on which.](docs/graph.png)

Live at [sys101.vercel.app](https://sys101.vercel.app).

## Why this exists

Learning system design from engineering blogs is hard because nothing tells you which post to read first, or what you need to know before it makes sense. Good posts assume background that a different post explains. sys101 orders concepts by their prerequisites and attaches vetted engineering posts to each one, so there is always a clear next thing to read.

## How it works

1. The graph is the homepage. Each node is a topic, and arrows point from what you should read first to what builds on it. A hollow node is unread and a filled node is read.
2. Each topic page has a short concept summary, what it builds on and leads to, a recap of the prerequisites, a digest of each company post (problem, walkthrough, diagram, numbers, trade-offs), a comparison when there are two or more posts, a glossary, common mistakes, a self-check quiz and a design exercise.
3. Reading progress is stored in your browser only. Nothing is sent to a server.

## How posts are chosen

A post is included only if it passes most of these:

1. **Specific.** Real numbers: latency, throughput, request volume, error rates.
2. **Honest about trade-offs.** What was tried, what failed, and why the final design won.
3. **Still relevant.** Describes architecture in use today, not abandoned infrastructure.
4. **Credible.** Written by the engineering team that runs the system at scale. No listicles or marketing posts.
5. **Transferable.** Teaches something that applies to a concept in the graph.

## Architecture

```
content/topics/*.json ──► next build ──► static HTML + Pagefind index ──► CDN (Vercel)
        ▲                     │
        │                     └── fails on missing prerequisites or empty sections
pipeline/ (offline, run by hand)
  fetch RSS ──► extract text ──► draft digests ──► human review ──► commit JSON
```

The site is read-heavy and its content changes rarely, so every page is generated at build time and served as static files from a CDN, with search running in the browser against a prebuilt index. The content pipeline is decoupled from the site and idempotent: it only produces JSON for review, so a failed or repeated run never affects what readers see.

## Stack

- Next.js (App Router) and TypeScript, every page statically generated
- Sigma.js and graphology for the graph
- Pagefind for search, built into static files at build time
- Vercel for hosting
- Pipeline in Node with rss-parser, Cheerio and Gemini Flash (scaffolded, not yet in use)

## Project structure

```
app/              routes: graph homepage, topic pages, terms, privacy
components/       graph view, topic page, index, search, read toggle
content/topics/   one JSON file per topic
lib/              content loading and build checks, graph layout, reading progress
pipeline/         offline scripts for fetching and summarizing posts
public/           static files; public/pagefind is generated by the build
docs/             images for this README
```

## Run locally

Requires Node 24 (see `.nvmrc`).

```
npm install
npm run dev            # http://localhost:3000
npm run search:index   # build the search index for local dev; rerun after content changes
npm run build          # static build, then the Pagefind index
```

The build fails if a topic lists a prerequisite with no topic file, if prerequisites form a cycle, if any section is empty (including each post's digest), if a quiz has fewer than 3 or more than 5 questions, or if a diagram uses gradients, filters or scripts or lacks a title.

## Adding a topic

Create `content/topics/<slug>.json`. A shortened example:

```json
{
  "slug": "cdn",
  "title": "CDNs",
  "group": "Scaling",
  "concept": "Two to four sentences on the idea itself.",
  "prerequisites": ["caching"],
  "primer": "A short recap of what the prerequisites taught.",
  "posts": [{
    "title": "Post title", "url": "https://...", "company": "Company",
    "digest": {
      "problem": "...", "constraints": "...",
      "walkthrough": [{ "step": "...", "explanation": "..." }],
      "diagram": "<svg viewBox=\"0 0 560 300\">...</svg>",
      "numbers": [{ "value": "...", "meaning": "..." }],
      "tradeoffs": { "chosen": "...", "rejected": "...", "why": "..." },
      "failures": "...", "takeaways": "..."
    }
  }],
  "glossary": [{ "term": "...", "definition": "..." }],
  "mistakes": ["...", "...", "..."],
  "quiz": [{ "question": "...", "answer": "..." }],
  "exercise": { "prompt": "...", "answer": "..." }
}
```

Before committing:

- Every prerequisite already exists as a topic.
- The post passes the selection rules above.
- The digest is written in your own words from the post itself, with no copied passages.
- Every number is checked against the post. Never estimate or round in a way the post does not.

## Content and attribution

Every post belongs to its authors. The digests are original write-ups of what each post says, and every topic page links to the original. To have a post removed or a digest corrected, email contact@example.com.
